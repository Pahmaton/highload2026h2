# Рассчётно-пояснительная записка для Курсовой работы по предмету "Проектирование высоконагруженных систем"

## 1. Тема и целевая аудитория

### Тип сервиса

Цифровой банк без сети отделений - платёжное ядро и клиентское приложение, спроектированные на примере Т-Банка.

Ниша подтверждена реальными аналогами: в России это Т-Банк, Сбербанк Онлайн, Альфа-Банк, Озон Банк; в мире - Revolut, Nubank, Monzo, Chime.

### Функционал MVP

Проектируется платёжное ядро и то, что его окружает на стороне клиента

1. **Главный экран**. Баланс на счетах и картах, лента операций с постраничной дозагрузкой.
2. **Авторизация карточной операции в реальном времени**. Обработка запроса от платёжной системы, проверка лимитов и текущего баланса, резервирование суммы при оплате.
3. **Перевод по номеру телефона**. Между клиентами одного банка и между клиентами разных банков через СБП, с проверкой получателя и подтверждением.
4. **Оплата товаров и услуг по QR-коду. Платежи по реквизитам поставщиков.**
5. **Push-уведомление по каждой финансовой операции**
6. **Поиск и фильтрация по истории операций**. По названию магазина или имени получателя, сумме, категории и периоду.

### Ключевые продуктовые решения
1. **Отделений нет - весь пользовательский трафик идёт через приложение.** Нет офлайн-канала, на который можно деградировать при отказе: недоступность API означает полную недоступность банка для клиента.
2. **Сервер - единственный источник правды по балансу.** Клиент ничего не считает локально и не хранит собственную копию баланса; при каждом открытии приложения он запрашивает актуальный баланс и новые операции, добавленные с прошлого запроса. Это осознанно смещает нагрузку на бэкенд в обмен на отсутствие расхождений в цифрах на экране.
3. **Двухфазная модель движения денег.** Оплата проходит в два шага: сначала банк резервирует сумму на счёте, а фактическое списание происходит позже, когда магазин присылает подтверждение (обычно через несколько часов или дней). Пока подтверждения нет, операция висит в ленте как "ожидает подтверждения", а доступный остаток считается как баланс минус сумму всех таких операций. Если подтверждение так и не пришло, резерв автоматически снимается по истечении срока (обычно нескольких дней).
4. **Баланс всегда точный.** Каждое движение денег записывается сразу с двух сторон - откуда списали и куда зачислили, - чтобы деньги нигде не терялись и не появлялись из ниоткуда. Если один и тот же запрос на списание придёт дважды (например, из-за повторной отправки при сбое сети), деньги спишутся только один раз. Ради этого баланс и проведенные финансовые операции обновляются мгновенно и без права на временное расхождение. Лента операций, поиск и аналитика так жёстко не ограничены - им можно обновляться с небольшой задержкой в несколько секунд.
5. **Получателя перевода ищут по номеру телефона, а не по номеру счёта.** Номера счетов пользователи не знают и не хотят вводить вручную. Но банк получателя заранее неизвестен - телефон может быть привязан к любому из сотен банков, - поэтому при каждом переводе банк отправителя должен на лету спросить внешнюю систему (СБП), в каком банке зарегистрирован этот номер, и только потом провести платёж. Это лишний шаг прямо в процессе перевода, который должен отвечать быстро и не может зависнуть в ожидании.
6. **Антифрод работает синхронно, прямо во время операции.** Решение по каждому платежу принимается за десятки миллисекунд; при превышении бюджета времени операция отклоняется.
7. **Push по каждой операции.** Уведомление о списании при отсутствии намеренной траты является для клиента основным сигналом о мошенничестве, поэтому канал доставки уведомлений проектируется как необходимый, а не вспомогательный.

**География.** Россия целиком. Для оценки потолка рынка: месячная аудитория интернета в России - 105 млн человек, 86% населения старше 12 лет [[5]](#список-источников). Таким образом сервис охватывает примерно треть интернет-пользователей страны. Аудитория распределена по 11 часовым поясам, что растягивает суточный профиль нагрузки и не даёт полноценного "ночного окна" для обслуживания.
 
**Масштаб рынка платежей, в котором работает сервис.** В I квартале 2026 года через СБП по стране прошло 4,7 млрд операций на 26,5 трлн ₽, в среднем 52 млн операций в сутки [[6]](#список-источников). Из них 3,2 млрд - переводы между физлицами и 1,4 млрд - оплата товаров и услуг на 2,4 трлн ₽ [[7]](#список-источников). За весь 2025 год в системе совершено 18,3 млрд операций на 103 трлн ₽ [[8]](#список-источников).
